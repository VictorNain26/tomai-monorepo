# Audit a11y WCAG 2.1 AA - Baseline 2026-04-21

**Scope** : 7 ecrans prioritaires + 8 composants UI de base
**Contexte legal** : EAA (European Accessibility Act) en vigueur depuis juin 2025 -> conformite WCAG 2.1 AA obligatoire pour apps vendues dans l'UE
**Methodologie** : audit read-only du code source. Verification manuelle (contraste couleur, lecteurs d'ecran, Dynamic Type 200 %) NON couverte ici - voir section "Outils pour test manuel".
**Auditeur** : Claude Code (statique, WCAG 2.1 AA checks traduits en proprietes React Native)

---

## Resume executif

| Priorite | Nombre de findings |
|----------|-------------------|
| **P0 (blocker EAA)** | 11 |
| **P1 (grave)** | 14 |
| **P2 (amelioration)** | 18 |

**Top 3 issues critiques** :
1. **P0-1** : `PronoteBadge` (parent dashboard + child summary) et les badges "d'urgence devoir" utilisent couleur SEULE (vert/orange/rouge) comme signal d'etat -> echec WCAG 1.4.1 "Use of Color".
2. **P0-2** : Nombreux `TouchableOpacity` icon-only (fermeture modale, X sur attachment, scroll-to-bottom) sans `accessibilityRole="button"` couples a des hit targets < 44 pt.
3. **P0-3** : Modal Level Picker sur `edit.tsx` (parent) : items de la liste `FlashList` sans `accessibilityLabel` ni `accessibilityRole`, et bouton "Fermer" = Pressable texte sans role.

Base positive : `Button`, `Input`, `AccountTypeToggle`, `ConfirmDialog` ont deja une instrumentation a11y correcte. Le composant `Text` derive automatiquement le role `header` pour h1-h4 + `aria-level` -> excellente fondation WCAG 1.3.1.

## Couleurs brand a verifier manuellement (contraste WCAG 1.4.3 / 1.4.11)

Tokens extraits de `src/lib/styles.ts` et classes Tailwind trouvees dans les ecrans audites. A tester avec [WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/) ou equivalent :

| Token | Valeur | A tester contre |
|---|---|---|
| Primary (blue-600) | `rgba(59, 130, 246, 1)` | Fond blanc `stone-50` + fond dark `stone-900` |
| Success | `rgba(5, 150, 105, 1)` (emerald-600) | Fond blanc + fond `bgColors.success[10]` |
| Warning | `rgba(217, 119, 6, 1)` (amber-600) | Fond blanc + fond `bgColors.warning[5]` (tres subtil, risque) |
| Destructive | `rgba(220, 38, 38, 1)` (red-600) | Fond blanc + fond `bgColors.destructive[10]` |
| Muted text | `stone-600 dark:stone-400` | Fond `stone-50` / `stone-900` / `stone-100` / `stone-800` |
| Text error in banner | `text-red-600 dark:text-red-400` | Fond `bgColors.destructive[10]` (10 % red sur blanc) |
| Text warning in badge | `colors.warning` sur `bgColors.warning[10]` | `PronoteBadge` "Non connecte" |

**Warnings specifiques** :
- `bgColors.warning[5]` (5 % opacite) + `text-amber-600` -> contraste probable < 4.5:1. A tester.
- Texte `stone-400` en dark mode (muted) sur `stone-900` -> contraste fragile.
- Placeholder input : `colors.muted` -> verifier contraste WCAG 1.4.11 (>= 3:1 pour UI).

## Outils pour test manuel

| Test | iOS | Android |
|---|---|---|
| Accessibility Inspector | Xcode -> Developer -> Open Accessibility Inspector -> Target Simulator | Accessibility Scanner (Play Store), capture une screenshot et analyse |
| Screen reader | VoiceOver : `Cmd + F5` (Mac sim) ou triple-clic bouton side (device) | TalkBack : Settings > Accessibility > TalkBack |
| Dynamic Type 200 % | Settings > Accessibility > Display & Text Size > Larger Text -> max | Settings > Display > Font size -> max + Display size -> max |
| Color blindness | Settings > Accessibility > Display > Color Filters | Settings > Accessibility > Color correction |
| Reduced motion | Settings > Accessibility > Motion > Reduce Motion | Settings > Accessibility > Remove animations |
| Contrast | [WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/) pour verifier les paires token/fond |

**Tests critiques a effectuer** :
1. **VoiceOver swipe sur login** -> verifier l'ordre logique : logo -> titre -> sous-titre -> toggle parent/eleve -> inputs -> bouton -> Google -> lien register.
2. **TalkBack sur chat** -> pouvoir : naviguer header, envoyer un message, joindre fichier, stopper la generation, naviguer messages.
3. **Dynamic Type 200 %** sur `DeckCard`, `ChildSummaryCard`, `HomeworkUrgentCard` -> verifier si `numberOfLines={1}` coupe des infos critiques (oui : `ChildSummaryCard:68`, `DeckCard:73`).
