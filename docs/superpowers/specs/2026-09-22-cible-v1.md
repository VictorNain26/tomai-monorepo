# Cible V1 — architecture et périmètre

Statut : validé le 2026-09-22. Remplace l'ADR 0001 (app universelle Expo), jamais
versionné, et la décision « mobile-only » du 2026-06-18.

## Produit

Assistant scolaire socratique pour élèves français, avec supervision parentale.
Tom est le nom de l'IA, pas celui de l'app (nom de produit à trancher, chantier
branding distinct). L'app n'est pas en production : aucun utilisateur, aucune
contrainte de rétrocompatibilité, on vise directement la cible.

Feature phare : un agent qui s'adapte à l'élève, nourri par Pronote (notes,
devoirs, emploi du temps).

## Décisions

| Sujet | Décision | Motif |
|---|---|---|
| Client V1 | **Web uniquement, Next.js** | Un seul client à livrer ; le natif sera réécrit plus tard avec sa propre UI |
| `apps/mobile` | **Supprimé** (l'historique git le garde) | Code mort à maintenir sinon : ~40 dépendances majeures en retard, CI dédiée, cache SQLite en clair |
| Topologie | **Un dépôt, backend en monolithe modulaire** | `ai-service` et `curriculum` séparés ont pourri puis été supprimés ; un service séparé ne se justifie que par une contrainte réelle |
| Serveur | Bun + Elysia conservés | Contrat Eden Treaty typé de bout en bout vers le client |
| LLM | **Mistral**, stack 100 % UE | Souveraineté, données de mineurs (RGPD) |
| Modèle de chat | **Mistral Small 4** (`mistral-small-2603`), multimodal | Voir `2026-09-22-agent-ia.md` |
| Référentiel de conception IA | Guides de certification Claude (Architect Foundations, Architect Professional, Developer Foundations), pratiques indépendantes du fournisseur | Pratiques reconnues, auditables |
| Pronote | Serveur uniquement (`pawnote`, GPL-3.0) | Tout l'écosystème Pronote actif est GPL : le garder côté serveur est une nécessité de conformité |
| Paiement | Web (remplace RevenueCat) | RevenueCat ne sert que les achats intégrés des stores |

## Monolithe modulaire

Chaque module expose une interface publique (`index.ts`) ; un module n'importe
jamais les fichiers internes d'un autre. Découpage cible, tiré du code actuel de
`apps/server/src` :

| Module | Responsabilité | Code actuel |
|---|---|---|
| `auth` | Comptes parent (email, Google) et élève (username), sessions | `lib/auth.ts`, `lib/auth-macro.ts` |
| `family` | Rattachement parent ↔ enfants, tableau de bord parent | `services/parent/`, `parent.service.ts`, `routes/api/parent.routes.ts` |
| `tutor` | Agent IA : session de chat, outils, mémoire, résumé, garde-fous | `services/chat/`, `lib/ai/`, `episodic-memory.service.ts`, `cognitive-profile.service.ts` |
| `learning` | Decks, cartes, révisions FSRS | `services/learning/`, `fsrs.service.ts`, `routes/learning/` |
| `documents` | Upload, extraction, analyse, stockage S3 | `services/document/`, `services/storage/`, `routes/file-upload.routes.ts` |
| `pronote` | Connexion QR, synchronisation, données scolaires | `services/pronote/`, `pronote-*.ts` |
| `billing` | Plans, quotas, abonnement web | `services/quota/`, `subscription.service.ts`, `token-quota.service.ts` |
| `voice` | Transcription et synthèse vocale (Voxtral) | `voxtral-*.service.ts`, `audio-transcription.service.ts`, `text-to-speech.service.ts` |
| `platform` | Config, DB, observabilité, erreurs, rétention RGPD | `config/`, `db/`, `lib/otel/`, `lib/errors.ts`, `retention-purge.service.ts` |

Ce qui disparaît avec le mobile : webhook RevenueCat, `push-token.routes.ts`,
`webhook-idempotence.service.ts`, la partie mobile de `packages/api`
(`cookieProvider`, `UPLOAD_CONFIG`) et le miroir TS des tokens pour NativeWind
dans `@repo/tokens`.

Le découpage physique en modules se fait au fil des lots, sur le code qu'on
touche, pas en un big-bang.

## Client web

- `apps/web` en Next.js (App Router), consommateur du contrat Eden via `@repo/api`.
- Primitives `@repo/ui` (shadcn) et tokens `@repo/tokens`.
- Le chat consomme le protocole de l'AI SDK (`useChat` de `@ai-sdk/react`), déjà
  celui du serveur.
- Pronote en web : le QR est scanné par la caméra du navigateur ou importé en
  image, décodé côté client, puis envoyé au serveur avec le PIN. Le serveur fait
  `loginQrCode` et impose son `deviceUUID`. La connexion ENT par WebView n'existe
  pas en web.

## Décisions ouvertes

Elles sont tranchées au démarrage du lot qui en dépend, doc-first, pas avant :

| Décision | Lot | Ce qui doit être vérifié |
|---|---|---|
| Next.js séparé qui appelle Elysia, ou Elysia monté dans une route Next | 3 | Doc Elysia (intégration Next.js), impact sur cookies et streaming |
| Hébergement web et serveur (UE) | 3 | Région UE, streaming SSE long, coût |
| Fournisseur de paiement web | 3 | Conformité UE, abonnement familial multi-enfants |
| Sort de `apps/landing` : conservée ou absorbée par `apps/web` | 3 | SEO, un seul déploiement |
| Décodage QR Pronote dans le navigateur | 3 | Bibliothèque maintenue, test sur vrais QR |
| Frontière GPL « service serveur ≠ distribution » pour `pawnote` | avant prod | Avis d'avocat |
| Nom de l'app | branding | Hors périmètre technique |
