# Maestro E2E Testing — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Set up Maestro E2E tests for 4 critical flows (auth student/parent, chat, flashcards) with testIDs and EAS Workflow integration.

**Architecture:** Add `testID` props to critical UI elements across 6 screens, create 4 Maestro YAML flow files, add Maestro config, and integrate into the EAS preview workflow.

**Tech Stack:** Maestro (YAML E2E), Expo SDK 55, EAS Workflows

**Spec:** `docs/superpowers/specs/2026-03-20-maestro-e2e-design.md`

**Prerequisites (before execution):**
- Compte test etudiant cree sur API staging : username `e2e_student_test`
- Compte test parent cree sur API staging : email `e2e-parent@test.tomia.fr` avec un enfant et un deck de flashcards
- Secrets configures dans EAS Dashboard : `E2E_STUDENT_USERNAME`, `E2E_STUDENT_PASSWORD`, `E2E_PARENT_EMAIL`, `E2E_PARENT_PASSWORD`

    clearState: true

## Task 4: Integrate Maestro into EAS Workflow

**Files:**
- Modify: `.eas/workflows/preview-android.yml`

- [ ] **Step 1: Add E2E job to preview workflow**

In `.eas/workflows/preview-android.yml`, add at the end:

```yaml
  e2e:
    name: Run E2E Tests (Maestro)
    after: [repack, build]
    type: maestro-test
    params:
      build_id: ${{ needs.build.outputs.build_id || needs.repack.outputs.build_id }}
      flow_path: e2e/
```

Note: If `maestro-test` type is not supported by the current EAS CLI version, this job will be skipped/fail gracefully. The testIDs and flow files are still useful for local Maestro testing.
